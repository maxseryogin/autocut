# Повторный запуск autocut в Oracle Cloud

По сохранённому журналу задача Terraform пыталась создать `autocut` в Милане,
`EU-MILAN-1-AD-1`: `VM.Standard.A1.Flex`, 1 OCPU, 6 ГБ ОЗУ. В момент запуска
Oracle ответил `Out of host capacity`. Журнал сам по себе не показывает текущую
доступность и не подтверждает, что это домашний регион аккаунта.

## Параметры для первой попытки

- Оставить A1 Flex, 1 OCPU и 6 ГБ: это уже настроено в исходном стеке и подходит
  как стартовая оценка для одного-двух пользователей, но не проверено нагрузкой.
  Распознавание GigaAM v3 F32 на процессоре может быть медленным; задачи
  субтитров в приложении выполняются по одной. Кадры при экспорте собирает
  браузер, а FFmpeg на сервере декодирует видео и формирует итоговый файл.
- Выбрать совместимый образ Ubuntu ARM64 с отметкой Always Free Eligible, если
  приходится выбирать образ заново. Сохранить прежний образ, если он подходит.
- Загрузочный диск: размер по умолчанию, если он в пределах бесплатной квоты;
  учитывать уже существующие загрузочные и блочные тома. Для модели, Docker и
  временных видео нужен свободный диск; модель при первом использовании
  скачивается и занимает около 900 МБ.
- Не задавать Fault Domain вручную. В журнале он автоматически выбирался.
- Проверить до создания отметку Always Free Eligible, домашний регион, остаток
  квот аккаунта и использование других ресурсов в консоли. Актуальные условия:
  https://docs.oracle.com/en-us/iaas/Content/FreeTier/freetier_topic-Always_Free_Resources.htm

Если A1 недоступен, можно повторить попытку позже. У Милана одна зона
доступности, поэтому переход в другую зону внутри Милана невозможен. Если текущие
1 OCPU/6 ГБ недоступны, уменьшение памяти может помочь размещению, но для GigaAM v3 F32
работоспособность на меньшем объёме не проверена. Бесплатный AMD Micro
с 1 ГБ памяти не следует считать равноценной заменой для этой модели.

## Повтор стека через Resource Manager

Журнал похож на задание Resource Manager. Если исходный запуск был сделан другим
способом, используйте его штатный механизм и не создавайте второй стек вслепую.

1. В консоли OCI выберите регион Milan, откройте **Developer Services → Resource
   Manager → Stacks**, выберите исходный compartment и исходный стек.
2. Проверьте состояние последнего задания и список Compute → Instances: после
   предыдущих попыток мог частично создаться ресурс. Не создавайте дубликат.
3. В стеке запустите **Plan**, дождитесь завершения и прочитайте план. В старом
   журнале было `1 to add, 0 to change, 0 to destroy`, но новый план может
   отличаться. Убедитесь, что создаётся только ожидаемая машина и нет неожиданных
   изменений или удаления; проверьте параметры и предполагаемую стоимость.
4. Выберите **Apply**, в **Apply job plan resolution** выберите последний
   проверенный Plan и запустите задание. Дождитесь итогового состояния и посмотрите
   журнал. Если снова `Out of host capacity`, повторите позже, предварительно
   проверив состояние стека и ресурсов. Не используйте Destroy для повтора.
5. При успехе найдите созданную машину и её публичный IPv4. Само создание VM не
   устанавливает приложение, если установка явно не предусмотрена вашим стеком.

Инструкция Oracle: https://docs.oracle.com/en-us/iaas/Content/ResourceManager/Tasks/create-job-apply.htm

## После создания машины

Продолжите по [инструкции развёртывания](README.md): SSH, Docker Compose, доступ
к TCP 80/443 в OCI и файрволе ОС, DNS, пароль и HTTPS. Порт приложения 8765
наружу не открывать. Установка Docker, совместимость зависимостей и работа модели
на этой машине ещё не проверены.

Клонирование репозитория на сервер получит только опубликованные коммиты.
Перед развёртыванием проверьте нужную версию; не копируйте на сервер личные
ключи, `.env` или локальные видео по умолчанию.
