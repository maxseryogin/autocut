# Онлайн-развёртывание для двух пользователей

Эта конфигурация рассчитана на одну виртуальную машину ARM64 или x86-64 с Docker Compose и публичным DNS-именем. Пример подходящего бесплатного ресурса — Oracle Cloud Always Free Ampere A1 в пределах актуальных лимитов аккаунта. Доступность виртуальной машины в выбранном регионе и условия бесплатного тарифа нужно проверить при создании.

## Что делает конфигурация

- Caddy получает и обновляет HTTPS-сертификат для указанного домена; наружу открыты только порты 80 и 443.
- Приложение работает за прокси. Вход защищён общим логином `autocut` и длинным паролем из `.env`; без пароля в облачном режиме приложение не запустится. Оба пользователя с этим паролем имеют доступ к одному экземпляру; изоляции между ними нет.
- FFmpeg и Python-зависимости устанавливаются в контейнере. Модель Whisper medium скачивается при первом запросе и хранится в отдельном Docker volume `model-cache`.
- Загруженные на сервер копии видео хранятся во временной файловой системе контейнера и могут исчезнуть при его пересоздании. Это не резервная копия; исходные файлы сохраняйте у себя. Задачи распознавания также сбрасываются при перезапуске приложения.
- Сервер не размещён и работоспособность контейнера в Oracle ещё не проверена. Импорт TikTok может зависеть от ограничений сервиса на запросы с облачных IP; доступна загрузка файла вручную.

## Подготовка сервера

1. Создайте в домашнем регионе виртуальную машину **Always Free Eligible**, не превышая бесплатные лимиты вашего аккаунта. Для текущей модели нужны несколько гигабайт памяти; на ARM подходит A1. Настройте доступ по SSH-ключу и установите Docker Engine с Compose по официальной инструкции для выбранной ОС.
2. В сетевых правилах Oracle и файрволе ОС разрешите входящие TCP 80 и 443. Доступ по SSH ограничьте своими адресами. Не открывайте порт приложения 8765 наружу.
3. Настройте DNS-имя на публичный IPv4 сервера. Подойдёт и имя формата `АДРЕС-IP.sslip.io` (сторонняя DNS-служба). Для выдачи сертификата имя должно разрешаться в адрес сервера, а порты 80 и 443 быть доступны извне.
4. Клонируйте репозиторий на сервер и в его каталоге выполните:

```sh
cp .env.example .env
chmod 600 .env
```

5. Откройте `.env` в редакторе и укажите `SPLITCLIP_DOMAIN` и длинный случайный `SPLITCLIP_PASSWORD` (не меньше 16 символов). Пароль можно сгенерировать командой `openssl rand -hex 24`. Не добавляйте `.env` в Git и не отправляйте его никому. Другу передавайте только адрес и данные входа безопасным способом.
6. Запустите `docker compose up -d --build` и проверьте `docker compose ps` и `docker compose logs`. Открывайте только `https://<ваш-домен>`. Если браузер сообщает об ошибке сертификата, не вводите пароль: проверьте DNS, порты и журналы Caddy.
7. При первом запуске субтитров дождитесь скачивания модели. Экспорт собирается в браузере в реальном времени. На телефонах может потребоваться выбрать HD и держать вкладку открытой; конкретные iPhone и Android необходимо проверить отдельно.

`docker compose down` останавливает сервисы, а `docker compose up -d --build` пересоздаёт контейнеры при обновлении кода. Перед обновлением дождитесь завершения проектов и скачайте результат: временные видео и задачи при пересоздании теряются. Не используйте `docker compose down -v`, если хотите сохранить модель и сертификаты.
